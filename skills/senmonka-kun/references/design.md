# Design methods

Use for visual/interface design critique and brand or presentation systems. Design quality includes communication and consistency, not personal aesthetic preference.

## Primary material

Actual screenshots at relevant breakpoints, design tokens, component library, content hierarchy, brand rules, accessibility constraints, implementation, and evidence about intended audience.

## Practical methods

1. **Visual hierarchy:** inspect scan order, contrast, emphasis, information density, alignment, grouping and focal points.
2. **System consistency:** compare typography, spacing scales, tokens, components, illustrations, imagery and interaction states.
3. **Content fit:** assess whether labels, claims, structure and emphasis communicate the purpose without misleading.
4. **Responsiveness:** check real mobile/desktop states, long strings, zoom, density, empty/error/loading states and contrast.
5. **Alternatives:** present a small number of concrete design directions, each with rationale, trade-offs and impact on existing brand decisions.
6. **Verification:** compare rendered outputs against specifications; use accessibility checks and observed user comprehension when possible.

Avoid subjective statements such as 'more modern' without criteria. A mockup is not proof of user preference or conversion uplift. If changing an approved visual language would help, present it as a proposal, not a silent redesign.
