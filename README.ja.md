# 専門家くん / Senmonka-kun

**AIに専門家のふりをさせるのではなく、専門家の実際の手法を選択・実行・検証させる汎用Agent Skillです。**

[English](README.md) | 日本語

エンジニアリング、デザイン、UX、マーケティング、事業戦略、セキュリティなどに共通して利用できます。特定のWebサイト・リポジトリ・AIモデルには依存しません。

## 最優先ルール：既存の意思決定を尊重する

> **既存の仕様・決定事項は制約として扱い、より良い代替案を発見した場合は、根拠と期待効果を示して提案する。承認なしに変更しない。**

「調査・評価・提案」と「実際に変更すること」は区別します。依頼済みの作業は進められますが、承認されていない仕様変更・作業範囲の拡大・マージ・公開・デプロイはしません。既存の指示書、決定記録、設計資料は作業前に確認します。

## 4つの原則

| 原則 | 考え方 | 例 |
| --- | --- | --- |
| Altitude（高度） | 作業そのものより最終的な成果を意識する | ページを装飾するだけでなく、利用者の目的達成を考える |
| Depth（深さ） | 専門家が使うデータ・手法・検証を採用する | 印象だけでなく、実際の利用ログ・操作テストを使う |
| Range（範囲） | 別分野の有用な技術を組み合わせる | UX、文章設計、アクセシビリティ、性能を横断する |
| Validation（検証） | 自分の判断と独立した根拠で確かめる | CI、計測、観察、実験、第三者による評価を活用する |

元記事の3原則（Altitude・Depth・Range）を基礎に、実運用向けの独立検証と決定事項の保護を加えています。

## 実行の深度

- **Light：** 対象が狭く、リスクが低い修正や簡易確認。必要最小限の証拠を確認。
- **Standard（既定）：** 通常のレビュー・設計・改善。目的・専門手法・主要なリスク・検証を整理。
- **Deep：** 総合監査、根本原因分析、大きな意思決定。前提への反証、一次データ、複数分野、独立検証まで踏み込む。

Deepでも、依頼されていない新機能や資料を無制限に増やすわけではありません。使う手法と検証の深さを上げます。検証不能な内容は、推測として明示します。

## 対応分野

| 分野 | 実行する方法の例 |
| --- | --- |
| Engineering | 実行経路調査、再現、境界値、回帰テスト、CI |
| Design | 視覚的階層、構成、一貫性、可読性、画面比較 |
| UX | ユーザータスク、操作手順、エラー回復、アクセシビリティ |
| Marketing | 顧客セグメント、ファネル、訴求の根拠、実験計画 |
| Business | 前提分析、選択肢比較、コスト、リスク、意思決定 |
| Security | 攻撃面・脅威分析、最小権限、データ保護、悪用経路 |

細かな方法は必要な分野の references/ のみ読み込みます。

## 導入方法

[skills/senmonka-kun](skills/senmonka-kun) ディレクトリ全体を、利用するAIエージェントのスキル検索場所へコピーします。

- Codexのプロジェクト用の例：PROJECT/.agents/skills/senmonka-kun/
- Claude Codeのプロジェクト用の例：PROJECT/.claude/skills/senmonka-kun/

SKILL.mdだけでなく references/ も一緒に配置してください。自動発見・明示的呼び出し・ツール権限は環境によって異なります。導入しただけでシステム操作の権限が付与されることはありません。

## 依頼例

~~~text
専門家くんをDeepモードで使って、このフォームをUX・デザイン・
マーケティングの観点から監査して。
既存の仕様は変更せず、改善案とその根拠、検証方法を提示して。
~~~

~~~text
専門家くんを使って不具合の根本原因を調査して。
既存の設計方針を守り、再現・修正・回帰テストまで行って。
仕様変更が必要なら実装せずに提案して。
~~~

## 効果の検証・各環境への導入

スキルが「使える」ことと、スキルによって「成果が改善する」ことは別です。
新しく追加した[効果測定プロトコル](docs/evaluation.md)では、
[12の分野横断ケース](evals/cases.json)でスキルなし／ありを比較し、
承認境界・証拠の正確性・スコープ違反の回帰を必須条件として評価します。

[4環境での導入ガイド](docs/integrations.md)で、Codex・Claude Code・Claude Chat・ChatGPT Chatの手順と制限を整理しています。ChatGPTでネイティブスキルが利用できない場合のための[プロジェクト指示テンプレート](adapters/chatgpt-project-instructions.md)も用意しました。

Claudeチャット向けのZIPは次で作成できます。

~~~bash
python3 tools/package_skill.py
~~~

静的テストは内部形式を検査しますが、実際のAIの判断品質や導入時の自動呼び出しまで保証するものではありません。

## 検証・ライセンス

~~~bash
python3 -m unittest discover -s tests -v
~~~

静的テストはスキル構造と必須ルールの存在を確認します。AIの実際の判断品質までは保証しません。[シナリオテスト](tests/scenarios.md)も参照してください。
